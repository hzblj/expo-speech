# expo-speech

Yarn 4 + Turborepo monorepo for **`@hzblj/expo-speech`**: speech to text for Expo on SpeechAnalyzer (iOS 26),
SFSpeechRecognizer (before it) and Android's SpeechRecognizer, with word timing, a transcription queue with a cache,
and highlighting while the audio plays. Read the package's own `CLAUDE.md` before touching it.

| Path | What lives there |
| --- | --- |
| `packages/expo-speech/` | The published package: `src/` (JS, hooks, `TranscriptText`), `ios/` (Swift; `ios/Core` also builds as a SwiftPM package for Mac tests), `android/` (Kotlin), `plugin/` (the config plugin). |
| `apps/example/` | The example: a Formula 1 weekend's team radio (captured from OpenF1 into `src/f1/radio.json`), transcribed on the device and played back with its words lit, built from `@hzblj/kara-ui`. Private. |
| `media/` | Captures of the example (iOS and Android: radio, playback with its words lit, lab, languages, pit wall; two short playback videos), for the README and the libraries site. Taken from Release builds, status bar at 9:41. |
| `scripts/pack-check.mjs` | Packs the package as npm gets it, checks what ships, runs the plugin and type-checks a throwaway consumer. |
| `.changeset/`, `.github/workflows/` | Release notes, CI (Biome, types, tests, pack check) and the changesets release to npm. |

## Commands

```bash
yarn ios / yarn android   # run the example (dev client)
yarn prebuild             # clean `expo prebuild` of the example (builds the package's plugin first)
yarn lint / yarn typecheck
yarn test                 # JS and plugin tests (Node)
yarn test:ios             # Swift tests on the Mac: the engines transcribe real speech generated by `say`
yarn test:android         # Kotlin JVM tests (after `yarn prebuild`)
yarn pack:check
yarn changeset
```

## Conventions

- Commits are Jan Blazej's (`hello@janblazej.dev`), with no co-author trailers.
- Workspaces resolve each other's TypeScript source: the example maps `@hzblj/expo-speech` to `src/` (tsconfig `paths`,
  `metro.config.js`), so no build is needed to run it. The published entry points are `build/`.
- Docs copy (READMEs, JSDoc that becomes docs, changesets) has no em dashes.
- `yarn release` publishes through Yarn (`workspace:` ranges rewritten) and tags through changesets.
